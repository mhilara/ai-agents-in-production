# El cambio urgente es el que mas revisa

Los cambios que mas dano hicieron no fueron los grandes: fueron los urgentes,
los que se aplicaron sin revision porque habia presion.

Un despliegue manual para "salir rapido del incidente" dejo el servicio en crash
loop. El fix original era correcto; lo que fallo fue saltear el pipeline.

**Regla:** cuanto mas urgente es el cambio, mas barato sale revisarlo. El
pipeline no es burocracia: es lo que hace que el cambio sea reversible.
